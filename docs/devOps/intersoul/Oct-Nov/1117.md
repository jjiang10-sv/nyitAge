To prevent AWS from automatically resetting your Elastic Load Balancer (ELB) configuration, follow these steps:

1. Understand AWS Automatic Management

AWS uses automated processes to ensure the ELB adheres to best practices, including automatic changes for security and operational reasons. These changes might include:

	•	Updating security group rules.
	•	Modifying health check configurations.
	•	Adjusting backend protocol settings.

AWS might reset configurations to comply with these rules unless explicitly overridden or exempted.

2. Steps to Prevent Automatic Resets

a. Use Custom Load Balancer Configuration

	•	Avoid using managed features like AWS Elastic Beanstalk or specific auto-scaling templates, which might trigger automated updates.
	•	Create your ELB outside of these environments and manage it independently.

b. Lock Specific Configuration Settings

	•	Use AWS tools like AWS Config to monitor changes to ELB settings and trigger alerts or rollbacks when unauthorized changes occur.
	•	Example: Set up an AWS Config rule to detect unauthorized changes to LoadBalancerAttributes.

c. Disable ELB Managed Security Settings

For Classic Load Balancers:

	•	Update attributes like connectionSettings or securityGroups manually and monitor them.
	•	Use the CLI or API to adjust settings explicitly.

aws elb modify-load-balancer-attributes \
    --load-balancer-name your-elb-name \
    --load-balancer-attributes file://attributes.json

Example JSON:

{
    "ConnectionSettings": {
        "IdleTimeout": 60
    },
    "AccessLog": {
        "Enabled": false
    }
}

d. Tag Resources to Avoid Management

	•	Tagging resources with specific metadata may help in excluding them from managed updates in environments like Elastic Beanstalk.
	•	Ensure proper IAM permissions to avoid overrides by automated services.

3. Monitor Changes

	•	Use CloudTrail to track changes to ELB configurations and identify the source of resets.
	•	Use AWS Config rules to monitor and enforce compliance with your preferred settings.

4. Contact AWS Support

If resets persist despite your configurations:

	•	Open an AWS Support ticket to request that automatic changes be disabled for your ELB.
	•	AWS may offer a solution tailored to your use case.

By using the above methods, you can effectively control and maintain your ELB configurations without unwanted interference.

In AWS, if a Classic Load Balancer (CLB) is set up to automatically switch HTTPS protocol to TCP, it’s typically a result of misconfiguration, as CLB does not natively perform protocol translation (e.g., converting HTTPS to TCP). However, the following factors might explain or address the situation:

Possible Causes and Fixes:

	1.	Listener Misconfiguration:
	•	Ensure that the listener settings on the CLB explicitly map HTTPS to HTTPS, and not HTTPS to TCP.
	•	Configuration:
	•	HTTPS (port 443) on the frontend.
	•	HTTPS or HTTP on the backend (depending on your setup).
	•	Check the listener configuration in the AWS Management Console or through the AWS CLI:

aws elb describe-load-balancers --load-balancer-name <your-clb-name>


	2.	SSL Termination at Load Balancer:
	•	If the SSL/TLS certificate is uploaded to the load balancer, the CLB terminates SSL at the load balancer level. In such cases:
	•	The CLB sends plain HTTP or TCP traffic to the backend.
	•	To maintain HTTPS throughout, configure the backend to handle HTTPS.
	3.	Backend Protocol Misalignment:
	•	If the backend instances or services are listening on TCP instead of HTTPS, the CLB might route the traffic as TCP.
	•	Solution:
	•	Update the backend service to listen for HTTPS traffic if secure communication is required.
	4.	Improper Security Policies:
	•	The SSL policy used in the CLB might be forcing the protocol to downgrade.
	•	Update the SSL policy to a more modern configuration:

aws elb set-load-balancer-policies-of-listener \
  --load-balancer-name <your-clb-name> \
  --load-balancer-port 443 \
  --policy-names <policy-name>


	5.	CloudWatch Logs for Debugging:
	•	Enable access logging on the CLB to understand how requests are being routed and what protocols are being negotiated.

Steps to Fix the Issue:

	1.	Verify Listener Setup:
	•	In AWS Console: Go to EC2 > Load Balancers > Listeners.
	•	Ensure the front-end protocol (HTTPS) maps correctly to the backend protocol (HTTPS or HTTP).
	2.	Update Backend Instances:
	•	Ensure backend servers are configured to handle HTTPS if required.
	•	Update any security groups or firewall rules to allow HTTPS traffic.
	3.	Switch to Application Load Balancer (ALB):
	•	ALB provides better support for HTTPS, including native support for SSL termination and secure forwarding.
	4.	Monitor and Test:
	•	Use tools like curl to test how the traffic is being routed:

curl -v -k https://<load-balancer-dns>


	•	Analyze logs for redirection or protocol errors.

To create alerts in Prometheus using kube-prometheus-stack (often referred to as prom-stack) with Alertmanager, you’ll need to configure Prometheus rules and set up Alertmanager to handle and route those alerts. Here’s a step-by-step guide:

1. Configure Alerting Rules in Prometheus

To create alerting rules in Prometheus, you can add custom rule files that define the conditions under which alerts should trigger.

	1.	Add an alerting rule in Prometheus:
If you have access to the values.yaml file of the Prometheus Helm chart, you can define alerting rules directly there. Here’s an example of how to add a rule to alert when a target (service) is down:

prometheus:
  additionalPrometheusRules:
    - name: example-rules
      groups:
        - name: example-group
          rules:
            - alert: TargetDown
              expr: up == 0
              for: 5m
              labels:
                severity: critical
              annotations:
                summary: "Instance {{ $labels.instance }} down"
                description: "{{ $labels.instance }} of job {{ $labels.job }} has been down for more than 5 minutes."

In this example:
	•	The rule TargetDown triggers if any target has been down for more than 5 minutes.
	•	The severity label and summary and description annotations define the alert details.

	2.	Apply the changes by updating the Helm chart:

helm upgrade prometheus prometheus-community/kube-prometheus-stack -f values.yaml -n <namespace>



2. Configure Alertmanager for Alert Routing

Alertmanager handles alert notifications and can be configured to route alerts to various receivers, such as email, Slack, or PagerDuty.

	1.	Configure Alertmanager in the values.yaml file under alertmanager.config to specify routing and receivers. Here’s an example configuration:

alertmanager:
  config:
    global:
      resolve_timeout: 5m
    route:
      group_by: ['alertname']
      group_wait: 30s
      group_interval: 5m
      repeat_interval: 3h
      receiver: 'email-notifications'
    receivers:
      - name: 'email-notifications'
        email_configs:
          - to: 'your-email@example.com'
            from: 'alertmanager@example.com'
            smarthost: 'smtp.example.com:587'
            auth_username: 'your-smtp-username'
            auth_password: 'your-smtp-password'


	2.	Apply the Alertmanager configuration by updating the Helm chart with the modified values.yaml file:

helm upgrade prometheus prometheus-community/kube-prometheus-stack -f values.yaml -n <namespace>



3. Verify Alert Configuration

Once your alerting rules and Alertmanager configuration are set up:

	1.	Check Prometheus for active alerts:
	•	Open the Prometheus UI (http://<prometheus-url>:9090).
	•	Go to Alerts to view the configured alerts and their status.
	2.	Check Alertmanager for alerts:
	•	Open the Alertmanager UI (http://<alertmanager-url>:9093).
	•	Ensure that alerts appear here when the defined conditions are met and that they are routed to the specified receivers.

Example Use Case: Alert for High CPU Usage

For a practical use case, here’s how you might add an alert for high CPU usage:

prometheus:
  additionalPrometheusRules:
    - name: cpu-usage-alert
      groups:
        - name: example-cpu-group
          rules:
            - alert: HighCPUUsage
              expr: avg by (instance) (rate(node_cpu_seconds_total{mode="idle"}[5m])) < 0.2
              for: 5m
              labels:
                severity: warning
              annotations:
                summary: "High CPU usage on {{ $labels.instance }}"
                description: "CPU usage on {{ $labels.instance }} is above threshold for the last 5 minutes."

Testing and Monitoring Alerts

	•	Simulate Alerts: You can adjust thresholds in alert rules temporarily to trigger an alert.
	•	Monitor Notifications: Check if Alertmanager sends alerts to the configured receiver (e.g., check email inbox for email notifications).

Yes, you can still use Rancher to manage and set up alerts, even if Prometheus was installed with kube-prometheus-stack (often referred to as prom-stack). Rancher supports integration with Prometheus and Alertmanager, enabling you to create and manage alerts across your clusters.

To set up alerts in Rancher:

	1.	Configure Prometheus Integration: In Rancher, navigate to Cluster Explorer > Monitoring and ensure it detects your Prometheus installation.
	2.	Set Up Alert Rules: Go to Cluster Explorer > Alerts & Notifiers in Rancher. Here, you can define alerting rules by specifying conditions based on Prometheus metrics.
	3.	Configure Alertmanager: In kube-prometheus-stack, Alertmanager is typically included. Ensure that Alertmanager is exposed and reachable by Rancher. You may need to set up an Alertmanager notifier to integrate with services like Slack, PagerDuty, or email.

Rancher will manage alert rules through its UI, allowing you to define specific thresholds and conditions to trigger alerts based on Prometheus data. This gives you a centralized view and control over monitoring and alerting across all your clusters.
